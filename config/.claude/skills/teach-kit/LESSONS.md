# Lessons

## One idea, about ten minutes

A lesson teaches **one new idea** toward the mission. If it needs four, split it: a lesson that packed four (a key chain, a reload pipeline, rejection rules and five checks) scored 1 of 6, and the same material split into focused lessons scored 4 of 6.

## Anatomy

1. **Header**: a kicker ("Lesson N · about 10 minutes"), an h1 naming the skill as a verb phrase ("Trace an alert to its receiver"), a lede starting "By the end you can …", and a meta line with the pinned versions and the mission goal it serves.
2. **Recall cards** (from lesson 2 on): two or three, chosen from the learning records, on what was missed or is due for spacing, worded as new situations.
3. **Teach**: two to four short numbered sections, only the knowledge the skill needs, each claim cited, with one real example using real names and numbers.
4. **Practice**: at least one hands-on exercise besides the quiz; cases when a belief has to change ([PRACTICE.md](./PRACTICE.md)).
5. **The rule to carry**: one box with the sentence to remember.
6. **Quiz**: 5 to 7 questions on real situations (or the cases themselves, when the lesson is built from cases).
7. **Read next**: the single best primary source, what to read in it and how long that takes, then the invitation to ask questions.
8. **Sources**: numbered, pinned to the versions in use; then links to the reference page and the next lesson.

## Show transformations

Whenever one thing becomes another (what a user wrote → what the system loaded, source values → generated config, a label set → the groups it falls into), show a **transformation figure**: two code panes, each headed with its source file and line range or the live endpoint and date, with the changed lines highlighted (added, changed, removed) and an arrow naming what did the transforming. Use real files, not invented ones; if the source repo isn't available, show the live system's output and say so.

## Writing

- Define every project term on first use, and use the topic glossary's terms exactly.
- Be exact ("the chart ships 1.7.1", not "we upgraded"), short sentences, numbered decisions with a recommended answer.
- Before each example, write the sentence that introduces it: that's what plays while the reader looks at it.
- Stable ids on anything another page links to (headings, case questions); generated ids don't survive a cross-page jump.

## Reference pages

The compressed essence of one or more lessons, for lookup and printing: tables, rules, copy-ready commands, the exact error messages and their fixes. No narrative, no quiz. Test every command on the page against the real system before publishing it there; a reference page with a broken command is worse than none.
